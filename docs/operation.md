# 運用の決まり（地図を回し続けるために）

地図は、書き方がそろい、古いものを片付け続けて初めて正しく働く。ここでは、誰が・いつ・何をするかを決める。
書き方そのものは `CLAUDE.md`、地図の見方は `README.md` にある。

## 1. 役割

| | 人 | Claude |
| --- | --- | --- |
| 決める | マージする・Issue を閉じる・カタログに機能を足すか・決まりを変えるか・使わない機能を外すか | 決めない（案を出す） |
| 作業 | 頼む・見直しで選ぶ | 地図を読んでから作業する・書き方を守る・PR を出す・決まったことを実行する（閉じる文面、カタログの PR） |
| 確かめる | 地図と守り具合を見る | マージのあと、本番に出たか（デプロイ）を確かめる |

## 2. 毎回の作業（Claude）

1. **前**：コネクタで `map` → `feature` → `issue` を読む。どの機能・どの Issue の作業かを決める（決められなければ聞く）
2. **中**：`CLAUDE.md` の書き方で Issue と PR を書く
3. **PR**：説明の最後に申告の3つの見出し
4. **マージのあと**：本番に出たかを確かめる（GitHub の main のチェック「Workers Builds」が success か）。失敗していたら、すぐ人に知らせる。確かめずに次へ進まない

## 3. 週1回の見直し

- **いつ**：週に1回（曜日は人が決める）。Claude がコネクタの `review` を読み、案を添えて1つのまとめにして出す
- **並べるもの**（決めるのは人）：
  1. 古くなっている候補の Issue → 閉じる／その機能の「残り」に寄せる／そのまま
  2. どの機能にも当たらない作業 → カタログに足す／今の機能に含める
  3. 書き方の守り具合と、足りないもの → 決まりの書き方を直すか
  4. 申告の「足りなかった決まり」 → **決まりに足すか、一回限りかを分ける**（よく出るものは決まりに足す）
  5. 止まっているのに開いた Issue がある機能 → 続けるか、いったん閉じるか
  6. 貯めているのに画面で使っていないデータ → 使う予定があるか、止めるか
- **決まったら**：Claude が実行する（Issue を閉じる文面・カタログや決まりの PR）。人の OK なしに閉じたり消したりしない

## 4. カタログ（機能の一覧）の直し方

- 新しい機能は、作った PR の中で `src/catalogs.ts` に足す
- 名前を変えるときは、前の名前を `aliases` に残す（過去の PR・Issue の題を拾い続けるため）
- 機能を消す・まとめる前に、人に聞く
- 見た目・文書・テストのように、ほかの作業にもついてくるものは `fallback`（ほかに当たらないときだけ数える）

## 5. Issue の寿命

- 立てるとき：題「機能名：何をするか」、本文に「機能：」「閉じる条件：」
- 閉じるとき：閉じる条件を満たした PR に「Closes #n」
- やり残し：その機能の「残り」の Issue に足す（機能ごとに1つ）。分けるときは「#n の続き」
- 7日動かず、つながる機能も止まっている開いた Issue は「古くなっている候補」になり、週の見直しで扱う

## 6. 決まりそのものの直し方

- 週の見直しで「足りなかった決まり」と守り具合を見て、決まりに足すか一回限りかを分ける
- 決まりを変えるときは、この文書・`CLAUDE.md`・`README.md` のうち、関係するものを同じ PR で直す
- 2回続けて週の見直しで使われていない画面・機能は、外す案を出す（外すかは人。表とデータは残す）

## 7. ほかのリポジトリに広げる

1. まず idea-flow 自身で続ける（2週間をめど）
2. 守り具合が上がり、地図のつながりが確かになったら、weather-note-cf に広げるかを人が決める
3. 広げるときは、`CLAUDE.md` の書き方の節と Issue のひな形を、そのリポジトリへの PR で出す（出す前に相談）

## 8. 困ったとき

| こと | 見る所・すること |
| --- | --- |
| マージしたのに本番に出ていない | main のチェック「Workers Builds」。失敗なら Cloudflare のビルドの記録を人に開いてもらう。ビルド用の鍵が切れていたら（「組織を離れたユーザーのトークン」）、Worker の設定 → ビルド → API トークンを作り直して再試行（2026-11-27 に一度あった） |
| 地図に「読めませんでした」 | GitHub の鍵（`GITHUB_TOKEN`）に、そのリポジトリの Pull requests・Issues の読み取りがあるか |
| コネクタの地図が古い | `sync` で読み直す（ふだんは読むとき30分ごとに自動） |
| つながりが少ない | 書き方（PR に Issue の番号）が守られているかを守り具合で見る |
