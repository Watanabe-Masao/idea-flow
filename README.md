# idea-flow

リポジトリの決まり（CLAUDE.md・AGENTS.md・ROLE.md・スキル・docs）を「範囲」ごとに整理して、Claude に正しく届けるための道具。
決めるのは人。Claude はコネクタ（MCP）から読んで相談し、提案だけを出す。

- **見える化**：決まりを条項に分け、どこに効いているか・問題（重複・食い違い・届かない・機能していない）を出す
- **範囲**：文書を範囲（棚）に置くと、その範囲と下の範囲に効く。横には効かない。見出し・決まり1つまで外せる
- **相談**：ピン・書き換えを相談に出し、Claude が影響と副作用を返事する。人が承認する
- **届ける**：範囲の木から CLAUDE.md の道案内を作り、PR として出す（マージは人）

> 以前あった「Linear の課題と GitHub のコミットを時系列に並べるタスク管理」は外した（2026-11）。D1 の表（issues・commits・suggestions など）は消していない。

## 地図（機能ごとの稼働と Issue）

「決まり」タブの最初の「地図」。**機能の一覧（カタログ）**と、マージした PR（変えたファイル）・Issue から自動で作る。読むだけで、リポジトリには書かない。

- **カタログ**：`src/catalogs.ts`。機能ごとに、名前・入口・ファイルの正規表現・使うデータ・題の頭の言葉。いまは weather-note-cf だけ（2026-11-27 にコードを読んで作った22機能）
- **稼働**：機能ごとに、1日にマージした PR の数をマスの濃さで（3週間／2か月）。マスをなぞると、その日の PR が下に出る
- **状態**：直近7日に作業なし＝止まっている、直近4日に3件以上＝作っている、それ以外＝落ち着いた
- **Issue**：本文の「機能：」の行 → カタログで人が結び付けたもの → 題の頭（「満月の物語：…」）→ 題の言葉、の順に機能へ結び付ける。つながる機能がすべて止まっていて、7日以上動いていない開いた Issue は「古くなっている候補」
- **どの機能にも当たらない作業**：カタログに足すかを決める材料
- **Issue の経過**：「Issue の経過」に切り替えると、Issue ごとに立てた日から閉じた日（開いているものは今日）までを線で、つながるマージ（PR）を点で出す。つながりは、PR が閉じると書いたもの（closingIssuesReferences）と、PR の題・説明の「#番号」。開いている Issue の数の移り変わりも出す
- **データの流れ**：データ（外から取る・自前で貯める）と機能のつながり。貯めているのにどの画面も使っていないデータは赤い破線
- 取り込み：PR は GraphQL で50件ずつ古い順にさかのぼり、毎回いちばん新しく動いた50件も読む。Issue は毎回すべて読み直す。開いたときに一度自動で読む

## 作業の記録（Claude がしたこと）

「決まり」タブの最初の「記録」。マージした PR ごとに、次を並べる。判断はせず、ずれだけを目立たせる。

- **頼んだこと**（PR の題）と **変えたファイル**
- **範囲**：変えたファイルの場所から決める。範囲に置いた文書と、その文書が書いているパス（ファイルか3段以上のフォルダ）が受け持つ場所。同じパスを複数の範囲が書いていれば、共通の親に付ける
- **関係する決まり**：その範囲で効く文書（上の範囲から引き継ぐものも）と、「使わない」部分
- **Claude の申告**：PR の説明の「確かめた決まり」「決まりになく、自分で判断した所」「足りなかった決まり」（CLAUDE.md の道案内で書き方を決めている）
- **気になる所**：範囲外の文書や「使わない」と決めた部分を使った／その範囲の決まりを1つも確かめていない
- 取り込みは「新しい PR を読む」。変えたファイルは PR ごとに1回だけ読む（1回の呼び出しで10件まで）
- コネクタ：`idea_flow` の `activity`

## スマホだけで動かす（Cloudflare の Workers Builds）

1. D1 に `idea-flow` を作る（作成済み。ID は `wrangler.jsonc` に記入済み）
2. Workers & Pages →「作成」→「リポジトリをインポート」→ このリポジトリ。デプロイコマンドは `npm run deploy`
   （表の作成〔マイグレーション〕→ デプロイの順に自動で行う）
3. Worker の「設定」→「変数とシークレット」に、シークレットとして `ADMIN_TOKEN`（画面の合言葉）・`GITHUB_TOKEN`（読むだけ）・`MCP_TOKEN`（コネクタ）・`GITHUB_WRITE_TOKEN`（書き出し）を追加
4. Worker の URL を開き、合言葉を入れて「決まり」の「診断」から取り込む

`GET /api/selftest`（合言葉つき）で、bge‑m3 が動くか・次元数を確かめられる。

## 決まりの見える化（#8）

画面の「決まり」タブ。リポジトリの CLAUDE.md・AGENTS.md・ROLE.md・SKILL.md・決まりの文書（`docs/*.md` など、人が選ぶ）を**読むだけ**で取り込み、どこに効いているかと問題を表示する。GitHub には書き込まない。

- 文書ごとに「どう読まれるか」を出す：自動で読まれる（CLAUDE.md・AGENTS.md）／役割として（ROLE.md）／説明文で読まれる（スキル）／参照されたときだけ
- 見つける問題：重複・食い違いの候補・一時的な決まりの残り・読み込まれ方が重なるスキル・どこからも読まれない文書
- 機能していない・意味がなさそうな文書の候補（取り込みのたびに、リポジトリの .md を全部見る）
  - もう無いファイルを指している：文書に書かれたパスがリポジトリに無い。消したコミットも出す（同じ行に「消した」などと書いてある記録は除く）
  - 使っていない技術向けのスキル：説明文の技術（Vue・Svelte など）が package.json に無い。外から入れたスキルも対象
  - どこからも案内されていない文書：どの .md からも参照されず、範囲にも置かれていない（入口・フォルダの説明の README・GitHub のひな形・決まりとして選んだ文書は除く）
  - .md は GitHub の GraphQL で約40件ずつまとめて読む（GITHUB_TOKEN が要る。無いときは選んだ文書だけで調べる）
- 人が「問題ではない」にしたものは、取り込み直しても出さない
- ルールの寿命は、人が仕分けるまで「未分類」（#7 の設計の原則）
- しきい値：`rule_dup`（重複）・`rule_conflict`（食い違いの候補）・`rule_skill`（スキルの重なり）
- 取り込みは人がボタンで行う（毎朝の自動取り込みには入れない）。読むリポジトリが GITHUB_TOKEN の対象外なら、公開リポジトリだけ読める

### Claude のコネクタ（MCP）で見える化の結果を読む

会話の Claude が、見える化の結果を読んで人と相談するための入口。**いまは読むだけ**（リポジトリにもアプリのデータにも書き込まない）。

道具：`rules_overview`（文書と問題の件数）・`list_rule_findings`（問題の一覧）・`read_rule_doc`（文書を見出しごとに行番号つきで）・`search_rules`（意味の近い決まり）

つなぎ方
1. Cloudflare の「変数とシークレット」に `MCP_TOKEN` をシークレットで追加する（長いランダムな文字列）
2. Claude の設定のコネクタで、カスタムコネクタを追加し、URL に `https://<Worker のURL>/mcp/<MCP_TOKEN>` を入れる

> 合言葉は URL に入っているので、URL を人に見せないこと。漏れたら `MCP_TOKEN` を変えれば古い URL は使えなくなる。

## 範囲の木と変更リクエスト（#10）

「決まり」タブの各リポジトリに「範囲の木」。決まりの文書を範囲（例：画面、満月の物語）に付けると、**その範囲と下の範囲に効き、横の範囲には効かない**。例外で、ある文書のある見出しの決まりを、その範囲（と下）だけ外せる。

- 変更はすべて**変更リクエスト**になり、**人が承認したときだけ反映**する（人の操作も、Claude の提案も同じ入口）
- リクエストには「承認したら変わること」（範囲ごとに、効き始める文書・効かなくなる文書・例外の増減）を出す
- 範囲ごとに「Claude に渡す内容」（守る文書・使わない部分・範囲外）を見られる
- レントゲンで範囲を選ぶと、その範囲の決まりも届くものとして数え、例外の部分は外す
- コネクタ：`read_scopes`・`read_scope_contract`・`propose_scope_change`（提案だけ。反映は人の承認）

### 範囲のボード

「決まり」タブは「範囲・診断・レントゲン」に分かれる。「範囲」は、札（文書）を棚（範囲）に置く見た目のボード。

- **棚で見る／円で見る**：棚は作業台（置き替える）、円は地図（何が何を含み、どこが重なるか）
- **札を押す**：置く棚を選ぶ。棚から開くと「この棚では使わない部分」を見出し・決まり1つまで選べる（親にチェックすると下が全部、一部だけなら「－」の印）。例外は少ない書き方に直して保存する（見出しごと／決まり1つは `見出し ¶ 決まりの頭40文字`）
- **要約**：範囲・文書・見出しの1行要約を Workers AI（`@cf/meta/llama-3.3-70b-instruct-fp8-fast`）で作る。中身が変わったときだけ作り直す。失敗したら先頭の文で代用。正しいのは原文
- **原文**：決まり1つの元の書き方（表・箇条書きを整えて）と、GitHub の行へのリンク
- **見直しのピン・直接直す**：決まり1つに付ける。書き換えは文字単位の差分で見せる
- **変更 N件 → 確かめて確定**：範囲の変更はすぐ反映（履歴に残る）。ピンと書き換えは「相談」（承認待ちの変更リクエスト）になる。承認してもリポジトリは変えない（反映は今後の PR 書き出しで）
- **Claude に渡す文**：原文・書き換えたあと・効いている範囲・使わない範囲・意味の近い決まり（bge-m3）・答え方を自動でまとめる
- コネクタ：`idea_flow` の `consult`（承認待ちの相談の一覧／id で中身）・`comment`（相談への返事。アプリの相談に付く）

## Claude に届ける（書き出し）

「範囲」の「Claude に届ける」から。

- **CLAUDE.md の道案内**：範囲の木から「どの範囲なら何を読むか・何を使わないか」を作り、リポジトリの `CLAUDE.md` に入れる。Claude Code は CLAUDE.md を毎回自動で読む。`<!-- idea-flow:start -->`〜`<!-- idea-flow:end -->` の間だけを書き換え、手で書いた部分はそのまま（無ければ末尾に足す。ファイルが無ければ作る）
- **承認した書き換え**も同じ PR に入れる。書き換える前の文が1か所だけ見つかるときだけ当てる（見つからない・2か所以上なら入れずに知らせる）
- PR を出すだけで、**マージは人**。ブランチは `idea-flow/export-<日時>`
- 鍵：`GITHUB_WRITE_TOKEN`（Fine-grained。対象のリポジトリだけ、Contents と Pull requests を Read and write）。読む鍵（`GITHUB_TOKEN`）で読めないときは、この鍵で読み直す
- **claude.ai の会話用**：範囲のシートの「プロジェクト用の指示文」。プロジェクトの指示に貼ると、会話のたびに Claude がコネクタで契約（contract）を読む。決まりを変えても貼り直さなくてよい
- コネクタ：`idea_flow` の `export`（書き出す内容。読むだけ）・`project`（指示文）
